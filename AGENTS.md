## Правила

- PRD определяет цели, требования и границы продукта. Используй его ID требований в задачах, спецификациях и PR. Учитывай приоритет и целевую версию.
- Accepted ADR определяют согласованные технические решения. При конфликте с PRD зафиксируй расхождение и передай владельцу решения согласно CONTRIBUTING.
- Раздел «Вне рамок» PRD обязателен. Изменение объёма согласовывается до реализации.
- Для планирования декомпозируй только актуальную версию из roadmap. Спецификации следующих версий уточняй по мере необходимости.
- При проверке результата опирайся на критерии приёмки, контракты и применимые проверки проекта. Системные замечания ревью передавай владельцу области для актуализации соглашений.
- Официальные Agent Skills библиотек лежат в `.agents/skills/` (происхождение и обновление — `.agents/skills/README.md`). При конфликте их рекомендаций с Accepted ADR или PRD приоритет у проекта; расхождение фиксируется и передаётся владельцу решения.
- Ссылки описывают целевую структуру документации. Если нужный документ ещё не создан, используй существующие требования и согласованные ADR; при существенной неопределённости обратись к владельцу области.
