# Выкладка статической витрины

Документ описывает минимальный проверенный контур для issues #7 и #9. Схема соответствует ADR 0006 (VPS + Caddy) и ADR 0015 (неизменяемые артефакты, атомарное переключение указателя).

## Состав

- `dist/` — результат сборки Astro (`pnpm --filter site build`);
- `current` — symlink на активный релиз, который отдаёт Caddy;
- `releases/<UTC-метка>/` — неизменяемые копии артефактов;
- `releases/.previous` — путь к предыдущему релизу для отката.

## Требования к артефакту

Обязательны `index.html` и `404.html`. Отсутствие любого из них останавливает выкладку до переключения `current` (проверка в `scripts/deploy-static.sh`).

## Команды

Все команды выполняются из корня репозитория на VPS пользователем, имеющим доступ к каталогу выкладки.

```bash
# 1. Сборка и валидация контента (одна команда для чистого checkout)
uvx --from rust-just just build-site

# 2. Выкладка: копирует dist/ в releases/<UTC>, затем атомарно меняет current
scripts/deploy-static.sh deploy dist /srv/sreda/releases /srv/sreda/current

# 3. Проверка после выкладки
scripts/deploy-static.sh verify https://sreda.sielom.ru

# 4. Откат к предыдущему релизу
scripts/deploy-static.sh rollback /srv/sreda/releases /srv/sreda/current
scripts/deploy-static.sh verify https://sreda.sielom.ru
```

Caddy должен раздавать `/srv/sreda/current`, а не самый свежий каталог вручную: тогда переключение указателя — единственное изменение, которое нужно сделать для релиза или отката.

## Тестовый адрес

До закрытия Q-1 с Артёмом используется тестовый хост; Production-домен `sreda.sielom.ru` не переключается без решения Ильи (ADR 0006). Для проверки #7 публикуются две различимые сборки, проверяются главная и 404, затем показывается откат к первой.

## Секреты

Build-токены и ключи не должны попадать в статический артефакт (ADR 0015). Проверка секретов в истории — `just secrets` (gitleaks); в CI задачи выполняются с минимальными `permissions: contents: read`.

## Ограничения

- Откат возвращает только предыдущий релиз; более старые релизы удаляются по отдельной политике хранения.
- Скрипт не перезапускает Caddy: конфигурация раздачи `current` создаётся заранее и не меняется при выкладке.
- Проверка `verify` констатирует доступность с того узла, где запущена; доступность из российских домашних и мобильных сетей проверяется отдельно (issue #8).
