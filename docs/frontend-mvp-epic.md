# Выпустить публичную витрину медийки для читателей из Telegram и VK

**Версия продукта — 0.1.** Читатель открывает ссылку из паблика на телефоне, читает статью или смотрит видео, переходит к другим материалам рубрики и может найти команду и контакты медийки. Карина принимает витрину для распространения в пабликах.

## Объём

Приоритеты и целевые версии определяет [PRD, §6–8](prd.md). При планировании дочерних задач использовать ID требований.

| Объём 0.1 | Что входит |
| --- | --- |
| Must · SITE-01–07, SITE-15 | Главная, команда, контакты, список рубрик, страница рубрики со статьями и видео по дате, страницы видео и статьи, вставки в статьях, страница 404 |
| Must · CONTENT-01–05 | Тип материала, одна рубрика, поддержка нескольких и гостевых авторов, Markdown с проверяемыми директивами, файлы и медиа в репозитории. Для публичного демо нужны статья и видео |
| Should · SITE-08–10, SITE-12–13 | Подсветка и копирование кода, страницы авторов, темы, RSS, OG-картинки и метаданные материалов |
| Could · SITE-11 | Локальные закладки |

Посетительская аналитика SITE-14 отложена. В 0.1 Astro собирает материалы из файлов. Связь с будущей CMS задаёт общий формат контента. Основания — ADR 0001 (Astro), 0002 (директивы), 0007 (монорепозиторий и CI), 0008 (источник контента по этапам), 0010 (модель) и 0014 (контракт).

## Совместная работа

Полина ведёт дизайн, Саня — реализацию. Оба могут предложить правку макета или интерфейса. Саня проверяет реализуемость макета на реальных материалах, Полина проверяет реализацию на preview. Например, если длинный заголовок на телефоне вытесняет признак видео, они подбирают решение на этой карточке и согласуют изменение в задаче. К Илье обращаются, если выбор меняет требование или объём релиза.

Полина и Саня сами декомпозируют эпик. Для старта уже описаны мобильный макет рубрики и страница 404 в [пробных карточках](pilot-tasks.md). У рубрики есть [спецификация SITE-04](specs/site-04-rubrics.md).

Дизайн, каркас Astro и подготовка CI начинаются параллельно. Пока Костя настраивает CI, Саня запускает проверки и сборку локально и прикладывает результаты к PR по CONTRIBUTING.md. Первая передача Косте — собираемый сайт с одним валидным материалом и воспроизводимой командой. Костя подключает её к CI и готовит preview по [инфраструктурному эпику](devops-foundation-epic.md). До подтверждения DNS команда может проверять сайт на временном адресе.

## Критерии закрытия

- [ ] На домене медийки доступны главная, «Команда», «Контакты», минимум две рубрики с видео и хотя бы одна статья. Карина открыла витрину и подтвердила, что ссылку можно давать в пабликах. Подтверждение приложено к задаче выпуска.
- [ ] По каждому Must из §7 для витрины 0.1 есть результат проверки. В частности, статьи и видео одной рубрики отсортированы от новых к старым, неизвестная директива останавливает сборку, а неизвестный URL возвращает HTTP 404.
- [ ] К задаче выпуска приложены результаты применимых проверок §8. Для фронтенда это в том числе мобильный Lighthouse Performance ≥ 90 на страницах материалов, оптимизация изображений и загрузки видео, клавиатурная навигация, контраст, alt, SEO и совместимость браузеров. Для выкладки команда прикладывает результаты из инфраструктурного эпика.
