# Roadmap медийки

Рабочий план от 22 ноября 2026 года. Объём и приоритеты требований определяет PRD 1.5 (§6–8). Ближайший результат для В. В. — показ работающей витрины. Карина попросила до конца выходных сохранить согласованный объём.

| Версия | Результат |
| --- | --- |
| 0.0 | Основа разработки, CI, дизайн, контент для запуска и согласование DNS с Артёмом |
| 0.1 | Публичная витрина на домене медийки. Команда проверяет Must и применимые NFR, Карина принимает сайт |
| 0.2 | Контент-план со сроками, ответственными и Telegram-напоминаниями. В. В. видит просрочки в режиме чтения, недельная сводка опциональна. Подготовка панели может идти параллельно с сайтом |
| 0.3 | Анонсы материалов сайта в Telegram и VK |
| 0.4 | Редакция статей и публикация из CMS по согласованному с Кариной приоритету |
| 0.5 | Аккаунты читателей |
| 0.6 | Анонимная предложка медийки |

Вопрос общеинститутской «корзины» отслеживается в Q-7 PRD. В. В. рассматривает общий сайт. Интеграцию с CMS и порядок модерации можно оценить после выбора площадки. OAuth колледжа обсуждался условно. Для сотрудников действует Telegram с приглашением, для аккаунтов читателей предусмотрены Telegram и VK ID.

## Первый пробный цикл

Три пробные карточки заведены в [GitHub Projects](https://github.com/orgs/Sreda-Media/projects/1): [уточнение DNS (#3)](https://github.com/Sreda-Media/sreda-media/issues/3), [мобильный макет рубрики (#4)](https://github.com/Sreda-Media/sreda-media/issues/4) и [страница 404 (#5)](https://github.com/Sreda-Media/sreda-media/issues/5). Первые две можно взять параллельно. Илья уточняет DNS у Артёма. Полина готовит макет, Саня отвечает за его практическую реализацию и может ревьюить его сразу по готовности. После появления работающей сборки Саня берёт третью карточку. Остальные задачи нарезаются при подготовке соответствующей версии.

[Инфраструктурный эпик 0.0 (#9)](https://github.com/Sreda-Media/sreda-media/issues/9) ведёт Костян. Сначала включаются PR и независимое ревью, затем по результатам анализа переиспользования интегрируется CI. Временное исключение касается отсутствующего обязательного статуса при начальной настройке. После проверки CI этот статус становится обязательным, включая PR с документацией.

На неделе 23–29 ноября Костя готовит CI витрины. Минимальная зависимость для проверки сборки — доступный в репозитории Astro-сайт с одним валидным материалом; до этого можно подготовить правила PR и проверки workflow. [Витрина 0.1 (#10)](https://github.com/Sreda-Media/sreda-media/issues/10) читает файлы, контент-план 0.2 развивается параллельно. Переключение сайта на API запланировано на 0.4 после проверки общего контракта. До ответа Артёма проверки и демонстрация возможны на временном адресе; финальная приёмка на домене остаётся зависимостью выпуска.
