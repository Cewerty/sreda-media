# AGENTS — `apps/cms-web`

Редакционный веб-интерфейс микро-CMS (React). Часть монорепозитория Sreda Media.
Сначала читай корневой [`AGENTS.md`](../../AGENTS.md) и [`CONTRIBUTING.md`](../../CONTRIBUTING.md):
они определяют маршрутизацию контекста, роли и порядок согласования. Этот файл
уточняет их для фронтенда CMS и не отменяет принятые ADR.

## Границы

- Это `apps/cms-web`, а не сайт. Публичная витрина — `apps/site` (Astro, ADR 0001).
- Общие пакеты (`packages/remark-directives`, `packages/article-styles`) подключаются
  через pnpm workspace, а не копированием кода (ADR 0007, 0014). Пока их нет — не
  изобретай локальные дубликаты директив и стилей статьи.
- Не импортируй ничего из `apps/cms-api`. Связь с бэкендом — только через HTTP-контракт
  DMR/OpenAPI (ADR 0004 §11).
- Превью статьи обязано совпадать с сайтом: общие remark-плагины и стили (EDIT-01).

## Стек

TypeScript (строгий режим), React, React Router, Vite, Tailwind CSS +
`@tailwindcss/typography`, shadcn/ui, `react-markdown`, Biome, Vitest.

## Конвенции

- Алиасы: `@/*` → `./src/*`.
- Компоненты UI импортировать **только** из `@/components/ui`.
  **Не редактировать** файлы в `src/components/ui` — они генерируются shadcn.
- Страницы — в `src/pages`, локальные подкомпоненты — рядом с ними.
- Типы сущностей — в `src/types`.
- Новый UI-компонент: `pnpm dlx shadcn@latest add <name>`.
- Чистые функции (переходы, валидация, клонирование) держи отдельно от компонентов
  и покрывай Vitest: тесты не требуют DOM (`vitest.config.ts`, `environment: "node"`).
- Комментарии — только там, где объясняют неочевидное решение.

### Markdown и безопасность

- Без `dangerouslySetInnerHTML` и без `rehype-raw`.
- Стандартная безопасная обработка URL в `react-markdown`.
- Обычные переносы строк не превращаются в `<br>`.
- Заголовки разделов выводит приложение, а не Markdown-текст.
- Набор директив фиксирован; неизвестная директива — ошибка (ADR 0002, CONTENT-04).

### Состояние

- Владелец изменяемого состояния — один компонент-каркас; страницы получают данные
  и колбэки через `useOutletContext`. Route loaders не используются: они выполняются
  вне компонентного дерева и не имеют доступа к состоянию хуков.
- Редактор работает с независимой рабочей копией документа; исходные вложенные
  объекты и массивы не мутируются. Сохранение обновляет сохранённую версию.
- Прототип пока хранит данные в памяти (`src/hooks/use-mock-store.ts`,
  `src/data/demoData.ts`). Это временно до #25/#30: не добавляй localStorage,
  Redux/Zustand и не выдавай моки за интеграцию с API.

## Команды

Из корня монорепозитория:

```bash
pnpm install            # один раз, ставит workspace
pnpm dev:cms            # vite dev
pnpm verify:cms         # tsc -b --noEmit + tsc тестов + biome check --write src
pnpm check:cms          # biome check src (без записи, для CI)
pnpm test:cms           # vitest run
pnpm build:cms          # tsc -b && vite build
```

Перед коммитом — `pnpm verify:cms` и `pnpm test:cms`. Ошибки типов и Biome
исправляй по существу, не подавляй через `@ts-ignore` / `biome-ignore`.
